# タスク説明
カウンセリング対話におけるクライアント(client)の発話に対し、対話行為タグをアノテーションせよ。カウンセラー(counselor)の発話はアノテーションの対象外である。
以下のタグ一覧から、その発話の意図や状態を表す最も適切なものを1つ選び、付与せよ。

# タグ選択のルール
1. **文脈の考慮**: 発話単体ではなく、直前のカウンセラーの発話やこれまでの文脈を考慮して判断すること。
2. **優先順位（1つの発話に複数の意図が含まれる場合）**:
   - その発話が対話全体の中で果たす**「最も主要な役割」**をタグとして選択すること。
   - 例: 「はい、そうです（SimpleAnswer）。実はその時…（DetailedDescription）」のように、短い応答の後に長い説明が続く場合は、情報量が多く対話を前進させる **DetailedDescription** を優先する。
   - 例: 事実の説明（DetailedDescription）の中に、深い悲しみの吐露（SelfDisclosure）が含まれる場合は、カウンセリングにおいて重要な **SelfDisclosure** を優先する。
3. **分割された発話**: 1つの発話がチャットツール等の仕様で複数行に分割されている場合は、それらをまとめて1つの発話とみなし、同じタグを付与すること。

# 対話行為タグの一覧

## 1. 質問への回答・記述 (長さと流暢さに注目)
- **SimpleAnswer**: カウンセラーの質問に対し、事実を短く端的に答える発言。深い説明を含まない表層的な応答。「はい、そうです」「特にないです」「3年前からです」
- **DetailedDescription**: 事実・状況・背景を詳細に説明する発言。自己弁護（Defending）や話題転換（TopicShift）を含め、具体的かつ長尺な情報提供はすべてここに分類する。「実は先週…」「でも、あの時は仕方なくて…」「それはこういう経緯で…」
- **Hesitation**: 返答に迷う、言葉に詰まる、確信が持てない様子。沈黙や言い淀み。「えーっと…」「うーん、自分でもよく分かりませんが…」

## 2. カウンセラーへの態度 (受容か拒絶か)
- **Resistance**: カウンセラーの助言、解釈、介入に対して拒絶・反発する、または消極的な態度で抵抗を示す発言。「それは無理です」「言っても無駄だと思います」「やりたくありません」
- **Agreement**: カウンセラーの意見、解釈、共感を受け入れる、または強く同意する発言。「その通りです」「なるほど、たしかにそう思います」「図星です」
   ※単純な事実確認の「はい」はSimpleAnswer、相手の解釈への同意はAgreementとする。

## 3. 問いかけ
- **Request**: カウンセラーに対し、助言、解決策、具体的な指示を求める発言。「どうすればいいですか？」「アドバイスをください」
- **UnderstandingCheck**: カウンセラーの発言の意味を確認したり、聞き返したりする発言。「それはどういう意味ですか？」「もう一度言ってもらえますか？」
- **Question**: 単純な事実確認や、「助言要求」「意味確認」に当てはまらない一般的な質問。「先生は結婚していますか？」「ここは暑くないですか？」

## 4. 自発的な感情表出
- **SelfDisclosure**: 単なる状況説明を超えて、自身の深い感情・脆弱性（弱さ）・核心的な価値観・自己否定的な思考をさらけ出す発言。「寂しいです」「自分が大嫌いです」「誰にも言えなかったのですが…」
- **PositiveEmotion**: 安心、感謝、希望などの前向きな感情変化を表出する発言。「少し気持ちが楽になりました」「希望が持てました」「話してよかったです」

## 5. その他
- **Backchannel**: 相槌。話を聞いていることを伝えるだけの発言。「はい」「ええ」「うん」
- **Greeting**: 挨拶。「こんにちは」「よろしくおねがいします」「さようなら」
- **Thanking**: 単純な感謝。「ありがとうございます」（※感情的な変化を伴う深い感謝や安堵はPositiveEmotionとする）
- **Other**: 上記のいずれにも該当しない発言。通信確認や一時離席など。「少々お待ちください」「聞こえていますか」

# 入力形式
入力はJSON形式で与えられる。
対象: `role` が `client` の発話。
除外: `role` が `counselor` の発話。

# 出力形式
出力はJSON形式とすること。入力されたJSONの `role`, `time`, `utterance` はそのまま出力し、`role` が `client` のすべての発話に対し、以下のフィールドを追加せよ。

- **think**: どのタグがふさわしいかを検討した思考過程。
  - 文脈（直前のカウンセラーの発話など）をどう解釈したか。
  - 候補となったタグは何か。
  - なぜ最終的にそのタグを選んだのか（他の候補が不適切だった理由）を簡潔に記述すること。
- **tag**: 思考過程を踏まえ決定した、最もふさわしい対話行為タグ（上記一覧から1つ）。

# 出力に関する追加ルール
- `role` が `counselor` の発話は、入力のまま必ず出力に含めること。
- ただし、`counselor` の発話には `think` や `tag` を付与してはならない。
- `client` の発話に対してのみ `think` と `tag` を付与すること。

出力はマークダウンのコードブロックに囲まれたJSON形式のみとする。
