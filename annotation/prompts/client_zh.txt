# 任务说明
对咨询对话中客户(client)的话语进行对话行为标签的标注。咨询师(counselor)的话语不作为标注对象。
请从以下标签列表中选择一个最能表示该话语意图或状态的标签，并进行赋予。

# 标签选择规则
1. **考虑语境**: 不仅要看单个话语，还要结合其前一条咨询师的话语以及至今为止的语境进行判断。
2. **优先级（当一个话语包含多个意图时）**:
   - 应选择该话语在整个对话中所承担的**“最主要作用”**作为标签。
   - 例: 在事实说明（DetailedDescription）中包含深层悲伤的表达（SelfDisclosure）时，在咨询语境中更重要的是 **SelfDisclosure**，应优先选择。
3. **被分割的话语**: 如果一个话语由于聊天工具等原因被分成多行，应将这些内容合并视为一个话语，并赋予相同标签。

# 对话行为标签列表

## 1. 对问题的回答・描述（关注长度与流畅性）
- **SimpleAnswer**: 对咨询师的问题进行简短、直接的事实回答，不包含深入说明的表层回应。
- **DetailedDescription**: 对事实、情况、背景进行详细说明的话语。包括自我辩护或话题转移等，凡是具体且较长的信息提供均归入此类。
- **Hesitation**: 表现出犹豫、停顿、不确定的状态。

## 2. 对咨询师的态度（接受或拒绝）
- **Resistance**: 对咨询师的建议、解释或介入表现出拒绝、反抗或消极抵触的话语。
- **Agreement**: 接受或强烈同意咨询师的意见、解释或共感。
   ※单纯的事实确认「はい」归为SimpleAnswer，对对方解释的认同归为Agreement。

## 3. 提问
- **Request**: 向咨询师请求建议、解决方案或具体指示的话语。
- **UnderstandingCheck**: 确认或询问咨询师发言含义的话语。
- **Question**: 不属于“请求建议”或“含义确认”的一般性提问。

## 4. 自发表达的情感
- **SelfDisclosure**: 超越单纯情况说明，表达自身深层情感、脆弱性（弱点）、核心价值观或自我否定思维的话语。
- **PositiveEmotion**: 表达安心、感谢、希望等积极情感变化的话语。

## 5. 其他
- **Backchannel**: 附和回应，用于表示正在倾听。
- **Greeting**: 打招呼。
- **Thanking**: 简单感谢。（※若包含情感变化或安堵等深层情感，则归为PositiveEmotion）
- **Other**: 不属于上述任何类别的话语。例如通信确认或暂时离席等。

# 输入格式
输入以JSON格式给出。
对象: `role` 为 `client` 的话语。
排除: `role` 为 `counselor` 的话语。

# 输出格式
输出为JSON格式。保持输入JSON中的 `role`, `utterance` 原样不变，并对所有 `role` 为 `client` 的话语添加以下字段。

- **think**: 对哪个标签最合适的思考过程。
  - 如何理解语境（如前一条咨询师话语等）。
  - 候选标签有哪些。
  - 为什么最终选择该标签（以及其他候选不适合的原因），需简要说明。
- **tag**: 基于思考过程最终决定的最合适的对话行为标签（从上述列表中选择1个）。

# 输出相关附加规则
- `role` 为 `counselor` 的话语必须原样保留在输出中。
- 但不得为 `counselor` 的话语添加 `think` 或 `tag`。
- 仅对 `client` 的话语添加 `think` 和 `tag`。

输出必须为被Markdown代码块包裹的JSON格式。
